# 🏀 Basketball Tracking Analytics

Полностью автономное (офлайн) desktop-приложение на Python с графическим
интерфейсом [Streamlit](https://streamlit.io/) для аналитики баскетбольных
тренировок по видео со статичной камеры.

Приложение детектирует и трекает игроков и мяч моделью **YOLO11x**
(Ultralytics) с трекером **BoT-SORT + ReID**, математически определяет
броски/попадания в кольцо и передачи между игроками, автоматически нарезает
короткие MP4-хайлайты этих моментов и показывает итоговую статистику
(Box Score) прямо в интерфейсе.

Игроки в тренировочной форме **без номеров на майках** — идентификация и
удержание ID при трекинге строится на визуальных признаках (цвет формы,
обуви и т.д.) через модуль ReID трекера, а не на распознавании номеров.

## Возможности

- Загрузка видео тренировки (MP4/MOV) через боковую панель.
- Настройка зоны кольца (центр X/Y и радиус) прямо в GUI.
- Трекинг игроков (`person`) и мяча (`sports ball`) моделью YOLO11x на GPU
  (CUDA) с трекером BoT-SORT, настроенным на ReID по внешнему виду.
- Математическая детекция бросков/попаданий с кулдауном (защита от повторной
  фиксации одного и того же события).
- Детекция передач по смене владельца мяча в коротком временном окне.
- Автоматическая нарезка автономных MP4-хайлайтов: 5 секунд «до» события
  (кольцевой буфер в ОЗУ) + 2 секунды «после» (следующие кадры видео).
- Итоговая таблица статистики по игрокам и встроенный просмотр всех
  хайлайтов без выхода из приложения.
- Работает полностью офлайн после первого запуска (когда веса модели уже
  скачаны и закэшированы локально).

## Структура репозитория

```
.
├── app.py                  # Всё приложение (Streamlit GUI + логика трекинга/аналитики)
├── requirements.txt        # Python-зависимости с версиями
├── custom_botsort.yaml     # Конфиг трекера (генерируется автоматически при первом запуске)
├── highlights/             # Нарезанные MP4-хайлайты бросков и передач (авто-создаётся)
├── output_videos/          # Полные аннотированные видео обработанных тренировок (авто-создаётся)
└── README.md
```

`custom_botsort.yaml`, `highlights/` и `output_videos/` **не нужно создавать
руками** — `app.py` создаёт их автоматически при первом запуске, если их нет.

## Требования к железу и ПО

- Python 3.10–3.12.
- Рекомендуется NVIDIA GPU с CUDA (протестировано для **RTX 4080**). Без GPU
  приложение тоже запустится и обработает видео на CPU, но заметно медленнее
  — интерфейс выведет предупреждение, если CUDA не найдена.
- Интернет нужен **только один раз** — для скачивания весов модели YOLO11x и
  весов ReID-модуля трекера при первом запуске. После этого всё работает
  офлайн (веса кэшируются локально Ultralytics/PyTorch).

## Установка (Windows/Linux, RTX 4080)

1. Создайте и активируйте виртуальное окружение:

   ```bash
   python -m venv .venv
   # Windows:
   .venv\Scripts\activate
   # Linux/macOS:
   source .venv/bin/activate
   ```

2. **Сначала** установите CUDA-версию PyTorch/torchvision под вашу версию
   CUDA-драйвера (RTX 4080 поддерживает сборки CUDA 12.x). Проверьте актуальную
   команду на https://pytorch.org/get-started/locally/, например для CUDA 12.4:

   ```bash
   pip install torch==2.4.1 torchvision==0.19.1 --index-url https://download.pytorch.org/whl/cu124
   ```

   Это важно сделать **до** установки `requirements.txt`, иначе pip может
   поставить CPU-сборку torch с обычного PyPI.

3. Установите остальные зависимости:

   ```bash
   pip install -r requirements.txt
   ```

   (pip не переустановит уже стоящие подходящие версии torch/torchvision из
   шага 2, так как версии в `requirements.txt` совпадают — это ожидаемо и
   безопасно).

4. Запустите приложение:

   ```bash
   streamlit run app.py
   ```

   При первом запуске Ultralytics автоматически скачает веса модели
   `yolov11x.pt` (при недоступности — попробует официальный алиас
   `yolo11x.pt`) и веса ReID-модуля трекера — это требует интернет один раз.
   Все последующие запуски полностью офлайн, веса используются из локального
   кэша.

5. Приложение откроется в браузере (обычно `http://localhost:8501`).

## Как пользоваться

1. В боковой панели загрузите видеофайл тренировки (MP4/MOV) со статичной
   камеры (весь двор/площадка должна быть в кадре, камера не двигается).
2. Задайте координаты центра кольца (X, Y в пикселях кадра) и радиус зоны
   кольца — проще всего один раз посмотреть на кадр видео и прикинуть
   координаты кольца на изображении.
3. При необходимости подстройте порог владения мячом, окно передачи и
   кулдаун события у кольца в дополнительных настройках.
4. Нажмите «🚀 Запустить обработку» и следите за прогресс-баром.
5. По завершении обработки в главном окне появится:
   - таблица **Box Score**: `ID игрока | Броски | Попадания | Точность (%) | Сделано передач`;
   - полное аннотированное видео обработки (папка `output_videos/`);
   - плеер со всеми нарезанными хайлайтами из папки `highlights/` — броски
     (`goal_ID<id>_frame_<N>.mp4`) и передачи (`pass_from_ID<A>_to_ID<B>_frame_<N>.mp4`).

## Как это работает (логика аналитики)

- **Трекинг без номеров.** Конфиг `custom_botsort.yaml` включает
  `with_reid: True` — трекер BoT-SORT удерживает ID игрока по визуальным
  признакам (форма/обувь), а не по номеру, с повышенным `track_buffer` (120
  кадров), чтобы не терять игрока при коротких перекрытиях.
- **Владение мячом.** Игрок считается владеющим мячом, если центр мяча
  находится не дальше заданного порога (по умолчанию 65 px, диапазон
  50–80 px в настройках) от его рамки (0, если центр мяча внутри рамки).
- **Передача.** Если владелец мяча сменился с игрока А на игрока Б в течение
  заданного окна (по умолчанию до 1.5 сек, диапазон 0.5–2 сек) — это
  засчитывается как успешная передача, игроку А добавляется +1 пас.
- **Бросок/попадание.** Событие «бросок» фиксируется при входе центра мяча в
  окружность (центр кольца, радиус), заданную в GUI, с кулдауном (по
  умолчанию 3 сек), чтобы одно и то же зависание мяча у кольца не
  засчитывалось многократно. Бросок засчитывается игроку, который последним
  владел мячом, либо (если владелец неизвестен) ближайшему к кольцу игроку.
  Через долю секунды после входа в зону программа анализирует направление
  полёта мяча (линейная аппроксимация вертикальной скорости): если мяч
  продолжает падать вниз и оказывается ниже кольца — засчитывается
  попадание; если мяч отскочил — попадание не засчитывается (бросок при этом
  всё равно учитывается в статистике попыток).
- **Хайлайты.** Программа постоянно держит в памяти кольцевой буфер кадров
  за последние 5 секунд. При фиксации гола/передачи в файл сохраняются эти
  5 секунд «до» + следующие 2 секунды «после» события — автономный
  MP4-ролик через `cv2.VideoWriter`.

## Ограничения и заметки

- Детекция «попадание/промах» — упрощённая математическая эвристика по 2D
  траектории мяча (без депроекции в 3D), рассчитанная на статичную камеру с
  видом на кольцо. Для нестандартных ракурсов может потребоваться подстройка
  координат/радиуса зоны кольца.
- Приложение рассчитано на одну статичную камеру, снимающую всю площадку.
- Если CUDA/GPU или интернет для первого скачивания весов недоступны,
  приложение не «падает» — оно покажет предупреждение в интерфейсе и
  продолжит работу (на CPU, либо в демонстрационном режиме без реального
  распознавания, если веса модели не удалось загрузить). Это защитное
  поведение для сред без GPU/интернета; на рабочей машине с RTX 4080 вся
  боевая логика трекинга и аналитики используется полноценно.
