# 🏀 Basketball Tracking Analytics

Полностью автономное (офлайн) desktop-приложение на Python с графическим
интерфейсом [Streamlit](https://streamlit.io/) для аналитики баскетбольных
тренировок по видео со статичной камеры.

Приложение детектирует и трекает игроков и мяч моделью **YOLO11x**
(Ultralytics) с трекером **BoT-SORT + ReID**, математически определяет
броски/попадания в кольцо и передачи между игроками, автоматически нарезает
короткие MP4-хайлайты этих моментов и показывает итоговую статистику
(Box Score) прямо в интерфейсе.

Игроки в тренировочной форме **без номеров на майках** — идентификация и
удержание ID при трекинге строится на визуальных признаках (цвет формы,
обуви и т.д.) через модуль ReID трекера, а не на распознавании номеров.

## Возможности

- Пошаговый мастер из 4 шагов: загрузка видео → превью и настройка зон/порогов
  → сопоставление игроков (ID → имя/номер) → полный анализ и статистика.
- Настройка **двух** зон колец (центр X/Y и радиус каждого) с наглядным
  превью-кадром, на котором окружности отрисованы прямо на изображении.
- Трекинг игроков (`person`) и мяча (`sports ball`) моделью YOLO11x на GPU
  (CUDA) с трекером BoT-SORT, настроенным на ReID по внешнему виду.
- Пороги владения мячом, окно передачи, «память» мяча при потере детекции и
  кулдаун события у кольца — всё настраивается слайдерами в GUI, без правки
  кода/yaml.
- Математическая детекция бросков/попаданий с кулдауном (защита от повторной
  фиксации одного и того же события) у каждого из двух колец.
- Детекция передач по смене владельца мяча в настраиваемом временном окне, с
  устойчивостью к коротким пропускам детекции мяча.
- Отладочный таймлайн владения мячом (expander на шаге 4) — видно каждую
  смену владельца, засчитана ли передача, и почему, если нет.
- Ручное сопоставление ID игрока → Имя/Номер по кропам с предварительного
  сканирования (номера на форме не видны камере и не распознаются
  автоматически).
- Автоматическая нарезка автономных MP4-хайлайтов: 5 секунд «до» события
  (кольцевой буфер в ОЗУ) + 2 секунды «после» (следующие кадры видео).
- Итоговая таблица статистики по игрокам (с именем/номером) и встроенный
  просмотр всех хайлайтов без выхода из приложения.
- Работает полностью офлайн после первого запуска (когда веса модели уже
  скачаны и закэшированы локально).

## Структура репозитория

```
.
├── app.py                  # Всё приложение (Streamlit GUI + логика трекинга/аналитики)
├── requirements.txt        # Python-зависимости с версиями
├── custom_botsort.yaml     # Конфиг трекера (генерируется автоматически при первом запуске)
├── highlights/             # Нарезанные MP4-хайлайты бросков и передач (авто-создаётся)
├── output_videos/          # Полные аннотированные видео обработанных тренировок (авто-создаётся)
└── README.md
```

`custom_botsort.yaml`, `highlights/` и `output_videos/` **не нужно создавать
руками** — `app.py` создаёт их автоматически при первом запуске, если их нет.

## Требования к железу и ПО

- Python 3.10–3.12.
- Рекомендуется NVIDIA GPU с CUDA (протестировано для **RTX 4080**). Без GPU
  приложение тоже запустится и обработает видео на CPU, но заметно медленнее
  — интерфейс выведет предупреждение, если CUDA не найдена.
- Интернет нужен **только один раз** — для скачивания весов модели YOLO11x и
  весов ReID-модуля трекера при первом запуске. После этого всё работает
  офлайн (веса кэшируются локально Ultralytics/PyTorch).

## Установка (Windows/Linux, RTX 4080)

1. Создайте и активируйте виртуальное окружение:

   ```bash
   python -m venv .venv
   # Windows:
   .venv\Scripts\activate
   # Linux/macOS:
   source .venv/bin/activate
   ```

2. **Сначала** установите CUDA-версию PyTorch/torchvision под вашу версию
   CUDA-драйвера (RTX 4080 поддерживает сборки CUDA 12.x). Проверьте актуальную
   команду на https://pytorch.org/get-started/locally/, например для CUDA 12.4:

   ```bash
   pip install torch==2.4.1 torchvision==0.19.1 --index-url https://download.pytorch.org/whl/cu124
   ```

   Это важно сделать **до** установки `requirements.txt`, иначе pip может
   поставить CPU-сборку torch с обычного PyPI.

3. Установите остальные зависимости:

   ```bash
   pip install -r requirements.txt
   ```

   (pip не переустановит уже стоящие подходящие версии torch/torchvision из
   шага 2, так как версии в `requirements.txt` совпадают — это ожидаемо и
   безопасно).

4. Запустите приложение:

   ```bash
   streamlit run app.py
   ```

   При первом запуске Ultralytics автоматически скачает веса модели
   `yolov11x.pt` (при недоступности — попробует официальный алиас
   `yolo11x.pt`) и веса ReID-модуля трекера — это требует интернет один раз.
   Все последующие запуски полностью офлайн, веса используются из локального
   кэша.

5. Приложение откроется в браузере (обычно `http://localhost:8501`).

## Как пользоваться (пошаговый мастер)

**Шаг 1 — Загрузка видео.** Загрузите видеофайл тренировки (MP4/MOV) со
статичной камеры (площадка с обоими кольцами должна быть в кадре, камера не
двигается).

**Шаг 2 — Превью и настройка зон.** На слайдере выберите секунду видео для
превью-кадра. Задайте координаты X/Y и радиус для **обоих** колец числовыми
полями — окружности сразу отрисовываются на превью-изображении для наглядной
проверки. Здесь же настраиваются:
   - порог владения мячом (px) — макс. расстояние от центра мяча до рамки
     игрока, при котором игрок считается владеющим мячом;
   - максимальное время передачи (сек) — сколько может лететь мяч от одного
     игрока к другому, чтобы засчитался пас;
   - память мяча при потере детекции (сек) — сглаживает короткие пропуски
     детекции мяча (смаз движения, перекрытие руками);
   - кулдаун события у кольца (сек) — защита от повторной фиксации одного и
     того же броска.

   Если на вашем видео передачи не засчитываются — увеличьте порог владения
   и/или окно передачи, и проверьте отладочный таймлайн на шаге 4.

**Шаг 3 — Сопоставление игроков.** Приложение запускает короткое
предварительное сканирование первых N секунд видео (на полном разрешении, тот
же трекер — чтобы ID совпадали с финальным анализом) и показывает по одному
характерному кропу на каждый найденный ID. Впишите имя и номер для каждого —
поля можно оставить пустыми, тогда в таблице будет использован плейсхолдер
«Игрок {ID}».

**Шаг 4 — Полный анализ.** Нажмите «🚀 Запустить полный анализ» и следите за
прогресс-баром. По завершении появится:
   - таблица **Box Score**: `ID игрока | Имя | Номер | Броски | Попадания | Точность (%) | Сделано передач`;
   - отладочный expander с таймлайном владения мячом — каждая смена
     владельца, засчитана ли передача и почему (или почему нет);
   - полное аннотированное видео обработки (папка `output_videos/`);
   - плеер со всеми нарезанными хайлайтами из папки `highlights/` — броски
     (`goal_ring<N>_ID<id>_frame_<N>.mp4`) и передачи
     (`pass_from_ID<A>_to_ID<B>_frame_<N>.mp4`).

Кнопки «← Назад» / «Далее →» позволяют вернуться на предыдущий шаг (например,
подправить зону кольца) без потери введённых данных; кнопка «🔄 Начать заново
с новым видео» на шаге 4 полностью сбрасывает состояние.

## Как это работает (логика аналитики)

- **Трекинг без номеров.** Конфиг `custom_botsort.yaml` включает
  `with_reid: True` — трекер BoT-SORT удерживает ID игрока по визуальным
  признакам (форма/обувь), а не по номеру, с повышенным `track_buffer` (120
  кадров), чтобы не терять игрока при коротких перекрытиях.
- **Владение мячом.** Игрок считается владеющим мячом, если центр мяча
  находится не дальше настраиваемого порога (по умолчанию 90 px, диапазон
  20–250 px — слайдер на шаге 2) от его рамки (0, если центр мяча внутри
  рамки).
- **«Память» мяча.** Если детектор не нашёл мяч в текущем кадре (смаз
  движения, блик, частичное перекрытие руками), приложение до
  `ball_memory_seconds` (по умолчанию 0.3 сек, слайдер на шаге 2) продолжает
  считать мяч находящимся в последней известной точке. Без этого короткие
  пропуски детекции ровно в момент приёма пасующим партнёром обрывали цепочку
  владения, и передача никогда не засчитывалась — это и было основной
  причиной нулевых передач на реальном видео.
- **Передача.** Если владелец мяча сменился с игрока А на игрока Б в течение
  настраиваемого окна (по умолчанию до 1.8 сек, диапазон 0.3–3.0 сек) — это
  засчитывается как успешная передача, игроку А добавляется +1 пас. Каждая
  смена владельца (в т.ч. отклонённая из-за слишком долгого перелёта)
  логируется и видна в отладочном таймлайне на шаге 4.
- **Бросок/попадание.** Событие «бросок» фиксируется при входе центра мяча в
  одну из ДВУХ окружностей (центр кольца, радиус), заданных в GUI, с
  кулдауном (по умолчанию 3 сек) для каждого кольца отдельно, чтобы одно и то
  же зависание мяча у кольца не засчитывалось многократно. Бросок
  засчитывается игроку, который последним владел мячом, либо (если владелец
  неизвестен) ближайшему к кольцу игроку. Через долю секунды после входа в
  зону программа анализирует направление полёта мяча (линейная аппроксимация
  вертикальной скорости): если мяч продолжает падать вниз и оказывается ниже
  кольца — засчитывается попадание; если мяч отскочил — попадание не
  засчитывается (бросок при этом всё равно учитывается в статистике попыток).
- **Хайлайты.** Программа постоянно держит в памяти кольцевой буфер кадров
  за последние 5 секунд. При фиксации гола/передачи в файл сохраняются эти
  5 секунд «до» + следующие 2 секунды «после» события — автономный
  MP4-ролик через `cv2.VideoWriter`.
- **Отладочный таймлайн.** На шаге 4 в expander «🔍 Отладка» видна таблица
  всех смен владения мячом (с кем, когда, засчитана передача или отклонена и
  почему) и график владельца мяча во времени — используйте это, чтобы
  подобрать пороги, если события не детектируются на вашем видео.

## Ограничения и заметки

- Сопоставление ID → имя/номер (шаг 3) основано на быстром сканировании
  первых секунд видео тем же трекером и конфигом, с явным сбросом состояния
  трекера перед каждым независимым прогоном — это максимизирует совпадение ID
  с финальным анализом на шаге 4, но 100% гарантии в редких случаях (например,
  если игрок отсутствовал в кадре во время сканирования) дать не может.
  Если ID разошлись — можно пересканировать или пропустить сопоставление.
- Детекция «попадание/промах» — упрощённая математическая эвристика по 2D
  траектории мяча (без депроекции в 3D), рассчитанная на статичную камеру с
  видом на кольцо. Для нестандартных ракурсов может потребоваться подстройка
  координат/радиуса зоны кольца.
- Приложение рассчитано на одну статичную камеру, снимающую всю площадку.
- Если CUDA/GPU или интернет для первого скачивания весов недоступны,
  приложение не «падает» — оно покажет предупреждение в интерфейсе и
  продолжит работу (на CPU, либо в демонстрационном режиме без реального
  распознавания, если веса модели не удалось загрузить). Это защитное
  поведение для сред без GPU/интернета; на рабочей машине с RTX 4080 вся
  боевая логика трекинга и аналитики используется полноценно.
